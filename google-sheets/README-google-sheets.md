# Заявки с сайта → Google Таблица

Схема простая и бесплатная: форма отправляет данные в **веб-приложение Google Apps
Script**, а оно дописывает строку в вашу **Google Таблицу**.

```
Лендинг (index.html + script.js)
        │  GET-запрос (JSONP: имя, контакт, пожелание, источник, страница, utm)
        ▼
Веб-приложение Google Apps Script (файл google-sheets/Code.gs)
        │  appendRow
        ▼
Google Таблица, лист «Заявки»  +  письмо на e-mail (по желанию)
```

Отправка идёт через JSONP — то есть запрос уходит тегом `<script>`. Так сделано специально:
Google не отдаёт CORS-заголовки, и обычный `fetch` не смог бы прочитать ответ. С JSONP
сайт видит настоящий результат: если заявка не сохранилась, посетитель увидит сообщение
с телефоном и почтой, а не ложное «Спасибо».

Настройка один раз, ~5 минут. Аккаунт Google подойдёт обычный.

## Шаг 1. Создайте таблицу

1. Откройте <https://sheets.new> — создастся новая пустая таблица.
2. Назовите её, например `LILA — заявки` (это имя таблицы, лист создаст скрипт сам).

## Шаг 2. Откройте редактор скриптов

В таблице: **Расширения → Apps Script**. Откроется редактор с файлом `Код.gs`.

Удалите оттуда всё, что есть, и вставьте содержимое файла
[`google-sheets/Code.gs`](Code.gs) из этого проекта. Сохраните: **Ctrl+S**.

## Шаг 3. Выполните setup() один раз

1. Вверху редактора выберите функцию **`setup`** (выпадающий список рядом с «Выполнить»/«Run»).
2. Нажмите **Выполнить**.
3. Google попросит разрешения: **Просмотреть разрешения → выбрать аккаунт → Дополнительные
   настройки → Перейти к проекту (небезопасно) → Разрешить**. Это стандартная проверка для
   собственных скриптов, доступ даётся только вашему же коду.
4. Вернитесь в таблицу — появился лист **«Заявки»** с шапкой.

## Шаг 4. Разверните веб-приложение

1. В редакторе скриптов: **Развернуть → Новое развёртывание** (Deploy → New deployment).
2. Тип: **Веб-приложение** (Web app). Нажмите шестерёнку, чтобы выбрать тип.
3. Заполните:
   - **Описание**: `приём заявок`
   - **Запуск от имени** (Execute as): **Я** (Me)
   - **У кого есть доступ** (Who has access): **Все** (Anyone)
4. **Развернуть** и скопируйте **URL веб-приложения** — он заканчивается на `/exec`,
   вида `https://script.google.com/macros/s/AKfycb.../exec`.

> «Все» здесь означает только то, что страница сайта может отправить POST. Читать
> таблицу посторонние не могут. Ссылку можно считать полусекретной.

## Шаг 5. Проверьте, что всё работает

Откройте скопированный `/exec`-URL прямо в браузере. Должен появиться ответ:

```json
{"ok":true,"service":"LILA leads","sheet":"Заявки","time":"..."}
```

Если видите это — веб-приложение живо.

## Шаг 6. Вставьте адрес в сайт

Откройте `script.js` и в самом верху найдите:

```js
var FORM_ENDPOINT = '';
```

Вставьте туда свой адрес:

```js
var FORM_ENDPOINT = 'https://script.google.com/macros/s/AKfycb.../exec';
```

Сохраните файл. Всё — теперь каждая отправка формы добавляет строку в таблицу.

Пока `FORM_ENDPOINT` пустой, форма работает «в демо-режиме»: показывает благодарность,
но **заявку не сохраняет** (в консоли браузера будет предупреждение).

## Шаг 7. Тест

1. Откройте сайт, заполните форму, отправьте.
2. Через пару секунд обновите таблицу — появится новая строка.
3. Статус новой заявки — `новая`. Дальше в столбце **Статус** можно вести работу:
   `в переписке`, `счёт отправлен`, `заказ`.

## Что попадает в таблицу

| Колонка | Что это |
|---|---|
| Дата и время | момент отправки |
| Имя | имя из формы |
| Контакт | телефон или Telegram |
| Пожелание | что человек хочет сшить |
| Источник | `Лендинг LILA` + utm-метки, если они есть в адресе |
| Страница | полный адрес страницы отправки |
| Статус | `новая` (проставляется автоматически) |

Таблица работает и как простейшая CRM: заявки можно выгружать, фильтровать по статусу,
делить доступ с коллегой.

## Полезно знать

- **Уведомления на почту.** В `Code.gs` задайте `var NOTIFY_EMAIL = 'you@mail.ru';` и сохраните
  скрипт — письмо будет приходить на каждую заявку. Разрешение на отправку почты у проекта
  уже есть (оно выдавалось при развёртывании), но чтобы письма начали уходить, после правки
  кода нужно выпустить новую версию: **Развернуть → Управление развёртываниями → ✎ Изменить →
  Версия: Новая версия → Развернуть**.
  Если доступ к почте вообще не нужен, удалите из `Code.gs` функцию `notify`, её вызов
  в `saveLead` и строку `var NOTIFY_EMAIL = ...` — тогда при следующем развёртывании
  Google перестанет спрашивать разрешение на отправку писем.
- **Поменяли код в `Code.gs`?** Изменения вступают в силу только после
  **Развернуть → Управление развёртываниями → ✎ Изменить → Версия: Новая версия → Развернуть**.
  Новый URL при этом получится только если выбрать «Новое развёртывание».
- **Нужно остановить приём заявок?** Сотрите `FORM_ENDPOINT` в `script.js` (пустая строка)
  или **Развернуть → Управление развёртываниями → Архивировать развёртывание**.
- **Защита от спама.** В форме есть невидимое поле-ловушка `company`; если бот его
  заполнит, заявка молча отбрасывается. Плюс скрипт не принимает заявки без имени и контакта.
- **Проверка результата.** Сайт ждёт ответ скрипта 20 секунд. Если ответ не пришёл
  или Google вернул ошибку, посетитель видит сообщение «Не получилось отправить»
  с телефоном и почтой — такие случаи видно в консоли браузера.
- **Ограничения Google.** Бесплатный лимит — 20 000 отправок в день, для лендинга это
  недостижимо много. Первый запрос после простоя может отвечать 1–3 секунды.
- **Размер запроса.** Данные уходят в адресной строке (это и есть механизм JSONP),
  поэтому поля в форме ограничены по длине: имя и контакт — 80 символов, пожелание — 300.
  Для заявок этого хватает с запасом; если нужно больше, скажите — переделаем на другой способ.

## Альтернативы

Если не хочется возиться с Apps Script:

- **Formspree / Web3Forms / Getform** — форма отправляется на их адрес, а они пересылают
  заявки на почту и показывают их в своём кабинете (бесплатные тарифы ограничены).
- **SheetDB / Sheet.best** — кладут REST-API поверх Google Таблицы; строка подключения
  меняется в `script.js` одной строкой.

В любом из этих вариантов достаточно поменять `FORM_ENDPOINT` — остальной код не затрагивается.
